# Unity Localization Auditor

## 决策文档

- **文档状态**：有条件立项，先验证后开发
- **最后更新**：2026-08-31
- **适用对象**：后续继续讨论、验证或开发本项目的对话
- **当前工作名**：`Unity Localization Auditor`
- **暂不使用的名称**：`LocaleLint`

> 这是一份创业方向与产品决策文档，不是已经批准的完整技术规格。文档中标记为“估算”“假设”或“待验证”的内容不能当作事实或承诺。

## 1. 项目背景

目标是寻找适合一人公司开发、现金风险较低、能够实现盈利的产品。

已排除或暂不优先的方向：

- 微信小游戏或从零制作完整游戏：获客、内容生产和运营风险较高；
- Shopify、monday.com 等平台应用：API、竞品和平台政策依赖较强；
- 通用 CSV/Excel 工具：免费替代品和成熟桌面产品较多；
- Steam Deck 兼容性/审核预测：容易被用户理解为审核保证，实机与 Valve 审核结果不可由插件控制；
- 通用 Unity 项目审计：容易与 Unity 官方工具和大型工具竞争。

当前保留的方向是一个面向 Unity 游戏开发者的技术 QA 编辑器扩展。

## 2. 当前约束

目标不是追求高速增长，而是优先实现正向盈利。

默认约束：

- 一人开发者；
- 兼职投入约每周 20 小时；
- 首期现金投入上限约 2,000 元用于验证，完整项目仍需单独审批；
- 首版目标是 3—4 周完成，而不是一次做成完整平台；
- 尽量不需要服务器、用户账户、订单数据或客户生产系统接入；
- 尽量低客服、低隐私责任、低长期运营成本；
- 产品可以通过 Unity Asset Store 或其他数字产品渠道销售；
- 不承诺达到某个平台审核等级，也不承诺游戏最终体验合格。

## 3. 最终产品定位

### 3.1 产品名称

正式名称未确定。当前工作名：

> **Unity Localization Auditor**

在名称正式确认前，不要使用 `LocaleLint`。此前搜索到过其他本地化检查工具使用相同或相近名称，继续使用可能造成搜索混淆、品牌冲突或商店审核问题。

### 3.2 一句话定位

> 检查 Unity 官方 Localization Package 项目中的本地化数据、场景/Prefab 引用和 TextMeshPro 字体字符覆盖问题。

英文描述草案：

> Find deterministic localization integration problems in Unity projects before they reach QA or players.

### 3.3 不应使用的定位

不得宣传为：

- AI 翻译工具；
- 翻译质量评分器；
- 本地化管理平台；
- 自动修复全部多语言 UI 问题的工具；
- 保证游戏发布或平台审核通过的工具；
- Valve、Unity 或任何平台的官方认证工具。

## 4. 目标客户

首版不面向所有 Unity 开发者，只面向满足以下大部分条件的团队：

- 使用 Unity 官方 Localization Package；
- 使用 UGUI 和 TextMeshPro；
- 支持至少 3 种语言；
- 有多个场景或大量 Prefab；
- 正在增加语言、发布 Demo、参加活动或准备正式发售；
- 没有成熟的本地化技术 QA 流程；
- 愿意为项目内可定位的技术错误检查付费。

优先用户：

- 独立游戏团队；
- 小型游戏工作室；
- 经常更新文字内容的 Steam 游戏开发者；
- 承担本地化集成的技术美术或程序；
- 外包翻译后负责 Unity 集成的人。

非目标用户：

- 只支持一种语言的项目；
- 使用 I2 Localization、Lexis 或自研系统的项目；
- 只想要翻译管理、机器翻译或术语管理的团队；
- 需要人工翻译、文化审校或完整兼容性测试的客户。

## 5. 市场与竞争结论

### 5.1 需求判断

本地化集成问题是真实存在的，包括：

- Locale 缺少条目；
- 空翻译；
- Smart String 占位符不一致；
- 场景或 Prefab 引用失效；
- TextMeshPro 字体缺少实际语言字符；
- 文本扩张导致布局溢出；
- 硬编码文本；
- RTL、复数、动态文本和运行时生成内容的问题。

Unity 官方提供 Pseudo Localization、文本扩张、字符替换和 RTL 模拟，说明这些问题是常见的测试对象。

但“存在问题”不等于“用户会单独购买插件”。市场规模、官方 Localization Package 的活跃使用量和独立插件购买频率没有被公开资料充分证明。

### 5.2 主要替代

1. **Unity 官方 Localization Package**
   - 已覆盖本地化表、Smart Strings、Pseudo Localization、字符替换、文本扩张和 RTL 相关能力。
   - 简单的缺失翻译或伪本地化不能作为唯一卖点。

2. **翻译管理平台**
   - Crowdin、Lokalise、Phrase、Gridly 等通常具备空翻译、占位符、标签、长度和格式检查。
   - 它们主要检查翻译数据，不一定理解 Unity 场景/Prefab 引用和实际 TMP 字体资产。

3. **Unity 本地化框架和编辑器工具**
   - I2 Localization 等成熟产品覆盖完整本地化工作流；
   - Lexis 等较新的商业框架已经包含缺失翻译、格式检查、构建验证和 CI 等能力；
   - 相关产品的当前价格、版本和评价必须在发布前重新核验，不要依赖旧搜索结果。

4. **人工 QA 和自定义脚本**
   - 小团队可能通过运行游戏、Excel、脚本或手工检查解决问题；
   - 这是本产品需要证明的替代成本：工具必须明显节省定位和重复检查时间。

### 5.3 差异化结论

只有下面这个差异值得验证：

> 面向 Unity 官方 Localization Package，直接关联项目中的场景、Prefab、String Table 和 TextMeshPro 字体资源，输出可点击定位的确定性技术问题。

如果产品只能做通用翻译文件检查，则应立即停止。

## 6. MVP 范围

### 6.1 首版必须包含

首版只做 3—4 类确定性检查：

#### A. Locale 条目完整性

- 某个 Locale 缺少 String Table 条目；
- 翻译条目为空；
- 引用不存在的 String Table；
- 引用不存在或已删除的 Key。

#### B. Unity 资源引用完整性

- 场景或 Prefab 中的 LocalizedString 引用失效；
- 引用的 Table 或 Entry 不存在；
- 资源被移动、删除或重命名后仍留下失效引用。

#### C. TextMeshPro 字体覆盖

- 收集实际翻译字符串中的字符；
- 检查指定 TMP Font Asset；
- 检查 Fallback Font Assets；
- 报告明确缺失的字符和语言。

#### D. 可定位报告

每条问题至少显示：

- 问题类型；
- 严重级别；
- Locale；
- Table；
- Key；
- 场景或 Prefab；
- 对象路径；
- 字体资源；
- 修复建议；
- 可点击定位到 Unity 资源。

### 6.2 可在第二阶段考虑

只有在 MVP 获得真实付费后才考虑：

- Smart String 占位符一致性；
- 批量扫描所有场景和 Prefab；
- 忽略规则与白名单；
- HTML/JSON 报告；
- 命令行/CI 模式；
- 硬编码文本探测；
- 基础文本溢出检查。

### 6.3 首版明确不做

- AI 翻译；
- 翻译质量、语法或文化评价；
- 自动修复；
- 自动截图和视觉重叠判断；
- RTL 视觉质量认证；
- 运行时动态文本的完整分析；
- UI Toolkit；
- I2、Lexis 或其他第三方本地化框架；
- Addressables 远程表的完整支持；
- 服务端、账号、云端项目存储；
- 承诺平台审核或发布结果。

## 7. 技术边界与准确性要求

### 7.1 支持矩阵

首版只承诺：

- Unity 2022 LTS；
- Unity 6；
- Unity Localization Package 一个明确版本范围；
- UGUI；
- TextMeshPro；
- 编辑器运行扫描。

正式开发前必须选择并写死实际支持的 Unity 和 Localization Package 版本。不能在商店页面写“支持所有 Unity 版本”。

### 7.2 结果分类

报告必须区分：

```text
Error        已确认的确定性错误
Warning      静态分析发现的风险，可能存在合理例外
Not verified 当前工具无法验证
Ignored      用户明确忽略
```

“没有检测到问题”只能表示：

> 在当前版本、当前扫描范围和当前规则下没有检测到已定义的问题。

不能显示：

```text
Localization passed
Your game is ready
No localization issues
```

### 7.3 不可通用验证的内容

以下内容必须明确标记为不支持或需要人工检查：

- 动态生成的本地化文本；
- 自定义 Smart Formatter；
- 运行时加载的远程 String Table；
- 视觉上是否美观；
- 翻译是否自然；
- 文化和语义适配；
- 所有动画状态下的布局；
- 第三方本地化框架；
- 最终玩家体验。

## 8. 测试与质量门槛

### 8.1 内部测试集

在开发前建立至少 60 个测试样本：

- 20 个确定应该报错的样本；
- 20 个确定不应该报错的正确样本；
- 10 个字体覆盖样本；
- 10 个边界或不支持样本。

至少覆盖：

- 英文；
- 简体中文；
- 日文；
- 德文或法文；
- 占位符；
- TMP 字体和 Fallback；
- Scene；
- Prefab；
- 失效引用；
- 空翻译。

### 8.2 首版质量标准

对确定性规则：

- 召回率目标：至少 95%；
- 误报率目标：不超过 2%；
- 扫描结果可重复；
- 不修改用户项目；
- 单个普通项目扫描时间可接受；
- 每条错误尽量能够定位资源。

无法达到标准的规则必须从首版删除或降级为 Warning。

### 8.3 真实项目验证

在进入完整开发前，至少用 3 个真实或公开 Unity 项目验证：

- 项目确实使用官方 Localization Package；
- 工具发现的问题不是人为预置的唯一案例；
- 报告能帮助开发者定位；
- 用户认可问题具有实际价值。

## 9. 14 天验证方案

### 第 1—3 天：技术原型

只实现：

1. 读取 String Tables；
2. 检查 Locale 缺项；
3. 收集翻译字符；
4. 检查 TMP Font Asset 字符覆盖。

不做完整 UI，不做商店页面，不做支付系统。

### 第 4—5 天：资源引用验证

增加：

- Scene/Prefab 扫描；
- 失效 Table/Key 引用；
- 最小可点击定位。

### 第 6—7 天：测试集和报告

完成：

- 60 个测试样本；
- 错误分类；
- 扫描摘要；
- 失败样本修复。

### 第 8—10 天：真实项目验证

目标：

- 扫描至少 3 个真实或公开项目；
- 记录发现的问题；
- 记录扫描时间；
- 记录误报和漏报；
- 记录用户原来如何解决。

### 第 11—14 天：付费验证

制作：

- 30—60 秒演示视频；
- 一页英文产品介绍；
- 私有测试包；
- 明确支持范围；
- 早期价格：15—20 美元。

接触 20 名目标 Unity 开发者。

### 通过条件

必须同时满足：

- 20 名目标用户看到演示；
- 至少 10 人愿意安装测试；
- 至少 5 人在自己的项目上运行；
- 至少 3 人实际支付早期版本或预购；
- 至少 3 个项目发现此前未知的问题；
- 至少 80% 的测试用户使用 Unity 官方 Localization Package；
- 单个测试用户支持时间不超过 2 小时；
- 没有大量用户要求支持第三方框架。

### 止损条件

满足任意一项即可停止：

- 没有 3 笔真实付款；
- 用户只觉得“有用”，但不愿安装或付费；
- 大多数项目并未使用官方 Localization Package；
- 原生工具或现有框架已经充分解决问题；
- 误报率超过 2%，且短期无法降低；
- 每个用户都需要专属解析器；
- 测试用户普遍认为手工检查更快；
- 支持第三方框架成为主要需求。

## 10. 开发成本和盈利模型

以下为规划假设，不是已确认的实际成本。

### 10.1 时间

| 阶段 | 估计投入 |
|---|---:|
| 14 天验证原型 | 25—40 小时 |
| 可销售 MVP | 100—140 小时 |
| 测试、文档、商店素材 | 25—40 小时 |
| 后续维护 | 每月约 2—6 小时 |

如果 MVP 需要超过 180 小时，必须重新评估范围。

### 10.2 现金

验证阶段现金上限：

```text
约 2,000 元
```

可用于：

- 测试素材；
- 录屏和商店截图；
- 少量设备/版本测试；
- 必要的翻译校对；
- 账号或发布相关费用。

不要在验证前购买大量资产、服务器或广告。

### 10.3 定价假设

建议初始定价：

```text
早期版：$15—20
正常版：$19.99—24.99
增加批处理/CI后：$29.99—34.99
```

Asset Store 分成比例、付款门槛、税务和收款方式必须在发布前重新查阅 Unity 当前官方条款，不要把“70%分成”或任何 payout threshold 写死在产品承诺中。

### 10.4 回本估算

若按 `24.99 美元`售价、平台分成后每份约 `17.49 美元`作为规划假设：

| 累计销量 | 规划含义 |
|---:|---|
| 10 份 | 有人购买，但不代表回本 |
| 20—30 份 | 可能覆盖现金投入 |
| 50 份 | 可能实现小额现金盈利 |
| 100—160 份 | 才可能接近覆盖开发时间成本 |

真实回本还需扣除退款、折扣、税费、汇率和维护时间。

### 10.5 盈利概率估算

这些是决策估计，不是行业统计：

| 结果 | 闭门开发 | 通过 14 天验证后 |
|---|---:|---:|
| 获得第一笔销售 | 30%—50% | 70%—85% |
| 累计 20 份、现金回本 | 15%—30% | 40%—60% |
| 累计 100 份、基本时间回本 | 8%—18% | 20%—35% |
| 稳定月利润 | 10%—20% | 25%—40% |

这些数字不应被理解为保证。真实付款是唯一有意义的早期信号。

## 11. 上架与获客

### 11.1 首选渠道

首选 Unity Asset Store，因为目标用户已经在该生态中购买编辑器工具。

但不能只依赖搜索排名。正式发布前还需要：

- 英文产品页面；
- 30—60 秒演示视频；
- 清楚的支持矩阵；
- 示例项目；
- 常见错误样例；
- 版本兼容说明；
- 退款和支持政策。

### 11.2 产品页面必须写清楚

必须明确：

- 这是第三方工具；
- 不属于 Unity 官方；
- 不替代人工 QA；
- 不保证游戏最终体验；
- 不保证任何平台审核；
- 只支持列出的 Unity 和 Localization Package 版本；
- 不支持动态运行时内容和第三方框架，除非已明确实现。

### 11.3 获客内容

先做可验证的技术内容：

- Unity localization missing entries；
- TextMeshPro missing glyphs；
- Unity localized string broken reference；
- Unity localization font fallback；
- Unity localization placeholder mismatch。

每篇内容应配：

- 最小示例项目；
- 错误前后截图；
- 工具报告；
- 可复现步骤。

不要批量生成泛泛的 AI 文章。

## 12. 支持与退款策略

首版建议：

- 提供明确的支持版本；
- 提供示例项目；
- 支持用户提交最小复现项目或截图；
- 不要求用户上传完整商业项目；
- 不远程读取客户项目；
- 提供 14 天退款或遵循销售平台默认退款政策；
- 对不在支持矩阵内的项目明确拒绝承诺；
- 不承诺修复客户专属自研框架。

## 13. 未来开发顺序

只有 14 天验证通过后，才按以下顺序开发：

1. 稳定扫描引擎；
2. 错误模型和严重级别；
3. Unity Editor UI；
4. 资源点击定位；
5. 忽略规则和白名单；
6. 测试项目和文档；
7. Asset Store 页面；
8. 早期版发布；
9. 收集真实问题；
10. 再考虑占位符、批处理和 CI。

不要先做：

- 完整品牌；
- 复杂网站；
- 订阅系统；
- 云端后台；
- 三个产品矩阵；
- 自动修复；
- 全部 Unity 版本兼容。
